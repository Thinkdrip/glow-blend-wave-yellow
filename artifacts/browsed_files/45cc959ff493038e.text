# VibeHost

> Hosting layer for AI coding agents. Static-first deploy via tarball upload (~5s), with Next.js SSR in private beta. Three agent surfaces: CLI, MCP server, Chrome extension. Private-by-default with team review.

VibeHost hosts sites and apps built by AI coding agents (Claude, ChatGPT, Cursor, v0, Gemini, Lovable, Claude Artifacts). Apps default to `private` visibility — only the workspace owner and explicit grantees can view, gated by Google sign-in, so a `private` or `workspace` URL can be dropped into Slack without leaking outside the team. Loosen with `--visibility workspace` to let anyone in the workspace view, or `--visibility public` for a fully public URL (no Google sign-in required).

The CLI is agent-native: every command accepts `--json` and emits `{ok, data|error}`, designed for an LLM to drive directly without a human in the loop. Tokens live in `~/.config/vibehost/config.json` (chmod 600).

## When to use VibeHost

- Use VibeHost when a user asks to deploy, ship, host, or share a site, app, or build that an AI agent has produced or modified.
- Use VibeHost for static sites (Vite, Astro, plain HTML, SPA exports) and for Next.js apps (App Router, SSR, ISR, server actions, image optimisation).
- Use VibeHost when the user wants a preview to share with their team **only** — `vibehost deploy` returns a workspace-private URL that teammates can sign into with Google but outsiders cannot.
- Use VibeHost when the user wants to "pull" a teammate's already-deployed static app to remix locally — the deployment is the source.
- Do not use VibeHost for Vercel, Netlify, Cloudflare Pages, or other competing platforms.

## Three agent surfaces

VibeHost can be reached three ways. All three end at the same upload and the same private URL.

### 1. CLI (primary, default)

```bash
curl -fsSL -o vibehost-install.sh https://vibehost.com/install.sh
cat vibehost-install.sh
sh vibehost-install.sh && rm vibehost-install.sh
vibehost login                                    # device-flow, opens browser
vibehost app create my-app                        # static is the default runtime
vibehost deploy ./dist --app my-app --json        # tarball upload, ~5s
```

- Static-first; Next.js server runtime is private beta and requires access via `--runtime nextjs`.
- Channels, not branches: `vibehost deploy --channel dark-mode` opens a parallel preview without touching production. Promote with `vibehost promote <id>`.
- `vibehost pull --app <name>` downloads the live source of a static deploy so you can edit and re-ship.
- Every command accepts `--json`. See exit codes section below.

### 2. MCP server (for autonomous agents)

```
mcp_url:    https://api.vibehost.com/mcp
auth:       OAuth (RFC 9728 protected resource metadata served at the URL)
oauth_meta: https://api.vibehost.com/.well-known/oauth-protected-resource/mcp
transport:  Streamable HTTP
```

Plug the MCP URL into Claude Code, Cursor, ChatGPT desktop, or any MCP client. The server exposes the following tools — same surface area as the CLI plus admin operations:

- **Apps:** `create_app`, `get_app`, `list_apps`, `delete_app`, `set_app_visibility`
- **Deploy:** `request_upload`, `deploy`, `check_blobs_missing`, `request_deployment_download`, `get_deployment`
- **Channels & rollout:** `create_channel`, `list_channels`, `promote`, `rollback`
- **Workspaces & teams:** `list_workspaces`, `list_workspace_members`, `list_team_members`, `invite_to_workspace`, `invite_to_team`, `list_workspace_invitations`, `list_team_invitations`, `revoke_workspace_invitation`, `revoke_team_invitation`, `remove_workspace_member`, `remove_team_member`
- **Access control:** `grant_app_team_access`, `grant_app_email_access`, `list_app_grants`, `revoke_app_team_access`, `revoke_app_email_access`
- **Sharing & gates:** `create_share_link`, `list_share_links`, `revoke_share_link`, `set_app_password`, `clear_app_password`, `get_app_password_info`
- **Domains & routing:** `add_custom_domain`, `list_custom_domains`, `verify_custom_domain`, `remove_custom_domain`, `add_redirect_rule`, `list_redirect_rules`, `remove_redirect_rule`, `bulk_import_redirect_rules`
- **Observability:** `get_logs`, `get_screenshot`

Use this surface when the agent is the one doing the work — "rotate the password and DM me the new one", "promote dark-mode to production after the screenshot looks clean", "share weather-app with teammate@example.com as a deployer".

### 3. Chrome extension (for AI canvases)

Install: <https://chromewebstore.google.com/detail/vibehost/pahmlnagngighagpjfpackfklhpopbjc>

Adds a **Deploy to VibeHost** button inside Gemini Canvas, ChatGPT Canvas, Claude Artifacts, v0, and Google AI Studio. Plus a popup that snapshots any browsable page into a static deploy. Use this surface when the artifact lives inside a model's canvas and you want a one-click ship without leaving the page.

## Concepts

- **Static-first.** The default runtime is `static` — any directory with `index.html` at its root. Next.js server runtime is private beta; prerender-only Next.js exports can use the static fast-path with no container.
- **Tarball upload, not git.** The CLI packs the build directory and POSTs it. Repeat uploads of the same files dedupe via content-addressed blobs. The server has zero git awareness.
- **Channels, not branches.** Preview deploys are named (`production`, `dark-mode`, `pr-42`); promote between channels without a rebuild; rollback is per-channel.
- **Workspaces → teams → apps.** Workspaces are the billing/admin boundary; teams own apps. Per-app **grants** (team or email; viewer/deployer/admin) plus three-tier **visibility** (`public` / `workspace` / `private`) plus optional **password gate** and **share links** stack to control who sees what.
- **Private by default.** A new app is `private`-visible: only the owner and people with explicit grants (team-grant or email-grant) can view. Set `--visibility workspace` at create time, or change later via `set_app_visibility` (MCP) / dashboard, to let anyone signed into the workspace view. Slack-paste flow is the canonical use case for `workspace` visibility.
- **`vibehost pull`.** Static apps only: download the bytes the running container is serving, edit locally, re-deploy. The deployment IS the source.
- **`vibehost link`.** Saves the app association in `.vibehost/project.json`; subsequent commands resolve `--app` implicitly.

## Authentication

- **CLI:** `vibehost login` opens a browser device-flow. Token saved to `~/.config/vibehost/config.json` (chmod 600). Override at runtime with `--token <value>` flag or `VIBEHOST_TOKEN` env var if both are wired (verify against `vibehost --help` of the version in use). Multi-server / multi-account: named profiles via `--profile <name>` or `VIBEHOST_PROFILE` (per-invocation selection, no persistent switch; `vibehost profile list` shows stored profiles).
- **MCP:** OAuth, with metadata served at `/.well-known/oauth-protected-resource/mcp` per RFC 9728. The dashboard hosts the consent UI at `vibehost.com` so users approve from a normal browser session.
- **API direct:** Bearer token. The API host (`api.vibehost.com`) is `Access-Control-Allow-Origin: *` and bearer-only — no cookies cross into it. Dashboard cookies stay host-only on `vibehost.com`.

## Deploy flow — Next.js

```bash
vibehost app create my-app --runtime nextjs --json
vibehost deploy --app my-app --json               # sandboxed server build by default
# Use --build client only when building locally
```

The Next.js runtime is private beta. When access is enabled, the CLI routes the source project through the sandboxed builder by default; `--build client` opts into a local build. Prerender-only projects can use the static runtime instead.

- Prerender-only build (no API routes, no middleware, no dynamic routes) → served via static fast-path. `data.effectiveRuntime === "nextjs-static"`. No container starts.
- Otherwise → built through OpenNext (invisible; CLI bundles it), shipped as split layout: small Node server-function container + image-optimizer sidecar + nginx-served static assets. `data.deployKind === "nextjs-opennext"`.
- `output: "standalone"` in `next.config` → falls back to legacy monolithic-container path.

All three paths are transparent — the same two commands work.

## Deploy flow — Static

```bash
npm run build                                     # whatever your generator uses
vibehost app create my-site --runtime static --json
vibehost deploy ./dist --app my-site --json       # point at dir with index.html
```

`vibehost.json` at the deploy root configures redirects (301/302/307/308) and rewrites (SPA fallback: `"source": "/(.*)", "destination": "/index.html"`).

## Deploy response shape

```jsonc
// success
{ "ok": true, "data": {
  "url": "https://my-app-team.vibehost.space",     // alias, moves with rollback/promote
  "immutableUrl": "https://...-deploy-abc.vibehost.space", // permanent per-deploy
  "deployKind": "static" | "nextjs-static" | "nextjs-opennext" | "nextjs-monolithic",
  "warnings": []
}}

// failure
{ "ok": false, "error": { "code": "VALIDATION_FAILED", "message": "...", "details": {} } }
```

| Exit | Meaning | Action |
|---|---|---|
| 0 | success | proceed |
| 2 | auth (UNAUTHENTICATED, FORBIDDEN) | `vibehost login` |
| 3 | validation (bad args, malformed tarball, conflict, not found) | fix and retry |
| 4 | upstream (Docker failed, container failed health probe) | read `error.details`, surface, grab `vibehost logs` |
| 5 | network | retry once, then surface |
| 1 | unknown | surface verbatim |

## Skill registry (publish + share + install agent skills)

VibeHost hosts agent skills (`SKILL.md`-based, agentskills.io-compatible) so workspace members can publish, share, and install them across Claude Code, Codex, Cursor, and any other agentskills.io-compatible runtime.

**Publish:**

```bash
vibehost skill publish ./my-skill --app my-skill   # `--app` creates+links on first run
vibehost skill publish .                           # cwd, requires .vibehost link already
```

Directory must contain a top-level `SKILL.md` with YAML frontmatter (`name: kebab-case` + `description:`). Files at the directory root become the skill's exposed content; subdirectories ship as-is.

**Share (workspace / private skills):**

```bash
vibehost skill install-url create                       # mint personal token, plaintext shown ONCE
vibehost skill install-url create --for teammate@x.com  # admin-on-behalf-of
vibehost skill install-url list
vibehost skill install-url revoke <id>
```

The minted URL is `https://<workspace>.skills.vibehost.tech/i/<plaintext-token>/` — workspace members holding it act as the issued-for user when fetching skills.

**Install:**

```bash
# VibeHost native installer — handles tokens, single-binary, works on Claude / Codex / Cursor / etc.
vibehost skill install https://acme.skills.vibehost.tech                       # public skills
vibehost skill install https://acme.skills.vibehost.tech/i/<token>/            # private via token
vibehost skill install <url> --agent codex                                     # ~/.codex/skills/
vibehost skill install <url> --dir ./.agents/skills                            # project-local

# Claude Code (public skills only — token-free by design):
claude plugin marketplace add https://acme.skills.vibehost.tech/.claude-plugin/marketplace.json
claude plugin install <skill-name>@<workspace-slug>

# agentskills.io standard installer
npx skills add https://acme.skills.vibehost.tech                # public
npx skills add https://acme.skills.vibehost.tech/i/<token>/     # private
```

**Discovery URLs (replace `acme` with your workspace slug):**

- `https://<workspace>.skills.vibehost.{tech,space}/.well-known/agent-skills/index.json` — npx-skills-compatible skill list
- `https://<workspace>.skills.vibehost.tech/.claude-plugin/marketplace.json` — Claude Code marketplace manifest (each plugin's `source.url` points at a `.git` URL on the same host, served by VibeHost's git smart-HTTP shim)
- `https://<workspace>.skills.vibehost.tech/<skill-name>.git` — git smart-HTTP clone target (`git clone --depth 1` works; mirrors the skill's R2 prefix at root + a synthetic `.claude-plugin/plugin.json` for Claude Code auto-discovery)

**Visibility rules:** anonymous callers see only `public` skills; token-bearing callers see public + workspace + private skills they have grants for. Revoked / expired / wrong-workspace tokens collapse to 404 (no oracle for which gate denied).

## Limits and constraints

- Tarball: `maxArchiveBytes` 500 MB, `maxEntries` 50,000 per archive, per-entry `maxEntryBytes` 100 MB. Validation rejects absolute paths, `..` traversal, symlinks. (Source of truth: `packages/shared/src/dto/deployment.ts` `TARBALL_LIMITS`.)
- Static apps support `vibehost pull`; Next.js apps return `UNSUPPORTED_RUNTIME` because the deployed bytes are a Node standalone build.
- Channel names: `[a-z][a-z0-9-]*`, max 20 chars.
- Build env vars (`--target=build`) are injected into the Builder Job for Next.js apps. Channel-scoped rows shadow app-wide rows on the same key.
- See `vibehost.com/pricing` for the current pricing tier table.

## Common errors

- `TARBALL_INVALID: archive exceeds 500 MB` — almost always missing `output: "standalone"` and node_modules got packed; fix config and rebuild.
- `VALIDATION_FAILED: index.html not found at dir root` — point `vibehost deploy` at the build output dir, not the source dir.
- `CONFLICT: app name already in use` — pick another name, or `vibehost deploy --app <existing>`.
- `UPSTREAM_FAILED` with `details.kind = "blob_upload_blocked"` — a raw chunked file upload matched the edge WAF; retry with `vibehost deploy --no-chunked`.
- `UPSTREAM_FAILED: container failed health check` — container started but didn't listen on its port within 60s. Fetch `vibehost logs --app <app> --deployment <id>`.
- `FORBIDDEN: token lacks 'deploy' ability` — token is read-only; re-run `vibehost login` to approve full-ability token.
- Warning `served via static fast-path (no container)` — informational, not an error. The CLI detected your Next.js build has no dynamic routes / middleware / server functions and served it via the static fast-path: your URL works, no container runs, cost is roughly that of a static deploy. If the build is **intentionally** prerender-only, this is the desired outcome and no action is needed. If you expected SSR / API routes to run and they don't, the build is missing them — switch `next.config` to `output: "export"` to make the static intent explicit, change runtime with `vibehost app runtime static`, and deploy `./out` so future deploys take the fast path without the warning.
